> 目的：把我们对话和你在工作区里的学习活动，变成**听得见的节律**——活跃时音乐变快变响，停下时渐慢渐隐。用声音监督，而不是用弹窗打扰。

## 二、信号怎么来的

| 信号 | 来源 | 权重 |
|---|---|---|
| 你发的消息 | `~/.workbuddy/projects/<工作区>/*.jsonl` 里 `message(role=user)` | 3.0 |
| 对话往返 | 同上 `message(role=assistant)` | 1.0 |
| 我在干活 | 同上 `function_call` 事件 | 0.8 |
| 学习产出 | 工作区文件被修改的 mtime（不含 .git / .workbuddy / 本目录） | 2.0 |
| **手动打卡** | 页面「打卡 +1」按钮 → `学习节律台/manual-pings.jsonl` | 3.0 |

> 只读时间戳和角色，不读、不传正文内容。
>
> **为什么要打卡**：你安静读字幕、做真题时既没有对话也没有文件变动，会被误判成"空闲"——正好惩罚了最该奖励的深度工作。自习时每个学习单元结束按一下「打卡 +1」，等价于你原本的 L1 知识获得记录，一键完成。

## 三、映射规则（都在 server.py 顶部，可调）

```
活动分 = 近 10 分钟所有信号的加权和
强度   = min(1, 活动分 / 25)          ← TARGET_SCORE
ramp   = 1（空闲≤3分钟）→ 0（空闲≥20分钟）线性衰减
fade   = 0.3 + 0.7 × ramp             ← FADE_FLOOR 兜底，永不归零
BPM    = 50 + 90 × 强度 × fade        ← 50~140
音量   = (0.22 + 0.78 × 强度) × fade
```

想更敏感就把 `TARGET_SCORE` 调小；想更宽容就把 `IDLE_GRACE_MIN` 调大；想彻底静音就把 `FADE_FLOOR` 改成 0。

## 四、音乐怎么叠

- **合成节拍**（底层）：Web Audio 现场合成底鼓 + 踩镲，速度跟着 BPM 走。变速不变调，50↔140 无缝。
- **MP3 背景**（铺底）：把音频文件放进 `学习节律台/assets/`，页面下拉框选中即可。它**不改变速率**（避免变调），只随活动调音量。
- 也可以不复制文件，用页面上的「临时选本地文件」直接挑一个 MP3。

## 五、状态语义

| 面板状态 | 含义 |
|---|---|
| 全速推进 | 近 10 分钟高强度（强度 ≥ 0.75） |
| 进行中 | 强度 ≥ 0.35 |
| 刚起步 | 有活动但量少 |
| 慢下来了 | 空闲超 3 分钟，音乐开始降速降音量 |
| 降至最缓 | 空闲超 20 分钟，音乐停在最低档（音量兜底 30%，不归零） |

## 六、接口（想自己接别的程序也能用）

| 接口 | 说明 |
|---|---|
| `GET /api/state` | 当前状态 JSON（bpm / intensity / volume / fade / ramp / status / today / timeline） |
| `GET /api/ping` | 记一次手动打卡 |
| `GET /api/assets` | assets/ 下的音频列表 |

## 七、已知限制

- 只统计**本机**、**本工作区**的会话；换工作区或换机器要改一下路径匹配（`WS_NAME`）。
- ActivityWatch 未接入（当前服务未运行）。想加窗口级活动（分辨你切去了哪个窗口），启动 AW 后可在 `server.py` 里加一个 `http://localhost:5600/api/0/` 的取数函数。
- 文件 mtime 会把「我替你更新 02/04/05」也算作活动——因为那通常由你汇报学习结果触发，方向是对的；若要更严格可只统计你自己手动改的文件。
