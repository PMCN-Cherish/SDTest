# 知识获得账本

> 每次学习结束后填写。这是 L1 Mastery 指标，是效能感的核心来源。
> 规则：只记录「真的获得了」的知识（能独立解题 / 能合上书写出），不记录「看了 / 学了」。

## 格式模板

```
## YYYY-MM-DD
- 获得：（具体知识点，不是章节名）
  验证：（怎么验证的——做对了哪道题 / 画出了什么图 / 能复述什么）
- 获得：...
  验证：...
- 未掌握：（今天没搞懂的，进入待攻克清单）
```

## 记录

## 2026-10-15（模块① 软件工程 · 基础训练第1条：需求工程）

- 获得：需求是**功能/非功能/设计约束**三类；含**数字指标**（时间/并发/容量）的一律是**非功能需求**
  验证：Q3 自测（"500人同时在线+响应≤2秒"）→ 首答错（答成功能），纠正后建立判据
- 获得：需求工程 6 步顺序 = **获取→分析→定义→规格→验证→管理**
  验证：Q1 排序自测 → 第1空对，第5步（验证）卡壳
- 获得：需求分析干三件事 = **分类 / 建模 / 消歧义**（其中"建模"产物=DFD+数据字典，直接支撑下午题1）
  验证：Q2 自测 → 只答出分类、建模，漏消歧义
- 未掌握：需求分析 vs 需求定义的**产物边界**（分析产模型，定义产 SRS）→ 进入待攻克清单
- 未掌握：6步中第5步"需求验证"的位置不牢 → 已记错题本
